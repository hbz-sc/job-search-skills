# 边改边学 LangGraph

每阶段先读概念，再定位代码，自己改一个条件，观察结果，最后用自己的话写五句复盘。下面的练习待用户实际操作，不由助手代填已掌握。

| 阶段 | 概念与代码入口 | 练习与预期 |
| --- | --- | --- |
| M0 | checkpointer.ts：磁盘保存器；thread_id 区分任务 | 运行 checkpoint 测试，关闭后重开仍有 count；换 thread_id 则没有旧状态 |
| M1 | state.ts 与 graph.ts：共享状态、节点和边；schemas.ts：输入输出合同 | 修改虚构 JD 的要求，查看 matches/gaps 的证据如何变化 |
| M2 | nodes/research.ts：模型提出工具调用，程序校验执行并返回 observation | 从 initialDetailIds 移除一个岗位；它应该多一次详情查询，不能任意读取文件 |
| M3 | nodes/review.ts：interrupt 暂停；service.ts：Command 恢复 | 在 waiting_review 时退出；重开后修改草稿；分析不会重新运行 |
| M4 | store.ts 与 budget.ts：业务幂等、持久预算；evaluation 文件：评估 | 同一个 review-id 重试，结果不重复；查看缺正文与不匹配的不同结论 |

## 五个容易混淆的地方

1. LangGraph 是编排运行时，模型是推理服务；图可以包含纯代码节点。
2. Tool Calling 是模型返回结构化请求；MCP 是对接外部工具的协议。本地函数工具同样可以构成 Agent。
3. checkpoint 保存状态与执行位置；业务数据库保存可查询的结果和操作账本，两者不是一张表。
4. interrupt 不是一直占用进程等输入；任务可以落盘后退出。恢复可能重新执行当前节点，因此中断前不能随意产生副作用。
5. 有证据 ID 不代表语义必然正确。程序能校验 ID 是否存在，仍需评估“这段经历是否真的支持该要求”。

## 面试自测

- 为什么这部分采用图，而不是一串固定函数调用？
- 你的 Agent 究竟自主决定什么，哪些事情由程序决定？
- 为什么详情工具不能接受任意 jobId、URL 或脚本？
- 如何避免模型一直调用工具？重启能否重置预算？
- 审核请求已处理但客户端没收到响应，重试会发生什么？
- 进程在模型返回后、缓存落盘前退出，会不会再次计费？（仍可能，不能承诺 exactly-once。）
- 信息缺失与能力不匹配如何区分？
- Java 全栈经验与这个项目如何结合？（业务系统能力与 Agent 编排能力分别证明，未接 Java 前不混写技术栈。）

学习验收：以上问题和现场修改练习由用户完成后再标记通过。
