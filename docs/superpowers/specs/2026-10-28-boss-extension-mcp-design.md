## 范围与验收顺序

这是跨 TypeScript、Python 和 Chrome 扩展的项目级改造，分三阶段验收，后阶段不得掩盖前阶段未验证项。

### 第一阶段：只读连接与诊断

- 用户在已有 BOSS 职位页点扩展的“连接此页面”；不新建浏览器、不登录、不创建或关闭用户标签。
- 稳定识别 tabId、documentId、页面类别、账号可核验信息、搜索框及可见职位列表。
- 连续多次只读检查不意外导航；观察到页面变化时立即标记，不自行恢复页面掩盖现场。
- 首版只读稳定性基线为同一绑定会话至少 10 次串行读取，覆盖至少 60 秒；每次核对 tab/document、页面类别和搜索框。它只是可重复的首轮验收，不代表长期稳定性保证。
- 通过本地测试页主动模拟页面导航、失效元素、扩展断连、本地服务退出、超时与重复请求；报告准确停在哪个边界。故障模拟不在真实 BOSS 页面做。
- 能分别证明“指令未收到”“执行前拒绝”“执行开始但结果未知”“完成并有页面证据”，禁止把这些状态统称为超时。

### 第二阶段：搜索与返回

- 在实际搜索框输入固定关键词，确认深圳筛选与搜索结果，读取一个职位详情并返回列表。
- 验证返回后关键词、城市、已处理职位集合与列表进度；保存稳定职位 ID/链接，不能只记行号。
- 不点击立即沟通，不发送常用语。

### 第三阶段：一次真实沟通验证

- 满足页面操作契约、账号核验和当前具体授权后，只验证一个尚未沟通的职位。
- 依次核对职位/公司/招聘者、点击立即沟通、打开常用语菜单、读取并选择第一条、必要时点击发送、核对本方消息及发送状态、返回结果列表。
- 是否选择常用语就直接发出，必须先通过页面契约核验；选中后不盲目再按 Enter。
- 此阶段成功不自动启用批量发送；批量上限/平台额度模式沿用明确的运行配置与授权。当前 manual_only 默认与历史额度记录不擅自删除，不因日期变化推定额度恢复。

## 模块与连接（下述实现选择为设计建议）

### 1. Chrome 扩展（Manifest V3）

扩展只对明确允许的 BOSS 域名/路径运行，内容脚本在隔离环境中操作 DOM。不存在任意代码执行 MCP 工具，不使用 chrome.debugger、远程调试端口、隐藏浏览器或远程下载脚本。

扩展 popup 提供：绑定当前 BOSS 页、连接状态、当前步骤、停止、断开。只维护一个绑定会话和一个执行中的动作。切换浏览器标签不自动切换绑定目标。

监听 tabs.onUpdated/onRemoved、webNavigation 主框架提交及 SPA 历史变化、内容脚本启动/退出和连接断开；结合 tabId、frameId=0、documentId 与扩展生成的会话随机标识记录。不跨域读取其他标签内容。意外新增页只记录必要元数据，不接管。

所需权限计划为 nativeMessaging、storage、webNavigation 及窄范围 BOSS host permissions；是否需要额外 tabs 权限由实现验证决定。首版不申请 cookie、debugger、全站 host permissions，不采集网络请求体。截图作为后续可选诊断能力，不是首版依赖。

后台必须依据 Chrome 提供的 sender.tab、sender.frameId、sender.documentId 核对内容脚本报告，不能相信消息正文自报的身份。不开 externally_connectable，不使用网页 postMessage 接收控制指令；网页文本仅作为数据，不能触发扩展工具或修改动作队列。

### 2. 本地 Python 服务：改造版 mcp-bosszp

采用 **Chrome Native Messaging** 连接扩展和本地 Python 进程，避免重建之前的 Welcome/WebSocket relay 授权流程。Chrome 在用户点击扩展连接时启动 native host；该进程的 stdin/stdout 专用于 Native Messaging 长度帧，日志只能写 stderr/诊断文件。

同一个 Python 进程同时运行 FastMCP 的本机 Streamable HTTP 服务，供 TypeScript 客户端调用。绑定 127.0.0.1 的系统分配端口，启动完成后原子写入 private/ 下的连接发现文件，包含端口、随机会话 ID 和本轮 bearer token。凭证不进入日志、截图、Git 或聊天输出；文件仅当前 Windows 用户可读写。MCP 校验 token、Host/Origin、协议版本和活动会话；不开放跨域通用访问。

扩展和 native host 由 Chrome 校验注册的扩展 ID；本地发现文件只供同一工作区客户端读取，旧文件必须经身份握手后才能使用。服务中断不自动接管其他进程/端口。

Windows 安装脚本仅注册本项目的 HKCU NativeMessagingHosts 键和本地清单，提供精确对应的卸载脚本。扩展由用户在 Chrome 中加载，安装/注册在设计与实施获批后进行，不在本轮设计阶段执行。需要稳定扩展 ID，采用固定开发用 public key；私钥不放进扩展或仓库。

本地服务使用单实例锁；扩展也只允许一个活动 native port。另一窗口/配置重复连接返回“已有会话”，不并发控制。

### 3. TypeScript 调度和 SQLite

增加独立 BossPages 实现及 MCP 业务客户端，复用 Store、run-lock、去重与恢复逻辑。旧浏览器适配器保留为历史实现，但在新模式运行时不会启动。

SQLite 业务库仍由 TypeScript 写入。Python 维护独立的动作执行日志（可用本地 SQLite），以免多个进程共享业务迁移和写事务；两者通过 runId/attemptId/requestId 关联。扩展 storage.local 维护写动作的去重状态，后台 worker 重启也不能再次执行相同请求。

## 业务工具契约

至少覆盖：

- inspect_session：只读连接、绑定目标、登录/验证/额度提示、账号核验能力。
- search_jobs / list_jobs / open_job / restore_search：关键词、城市、稳定职位标识及结果范围。
- open_chat：明确属于会产生联系的写动作，不能被包装为只读。
- inspect_chat / read_first_phrase：核对招聘者与职位，读取常用语第一条；读取不能点击该条。
- choose_first_phrase / submit_filled_phrase / inspect_send_result：区分直接发送、仅填入输入框、未知效果。
- get_action_result / stop_run / get_diagnostics：失败后查询已有动作结果；不会通过查询重新执行动作。

业务工具参数是固定结构，不接收任意 CSS、JS、URL 跳转指令。选择器属于经审阅的页面适配器，并记录版本。MCP 输入不能决定是否跳过账号、页面或发送状态检查。

## 操作状态机与重试

每个动作具有 runId、attemptId、requestId、step、目标页面及职位/会话标识、前置条件、deadline。事件序列为 issued → accepted → validated → executing → observed，或 rejected / failed / uncertain；executing 前必须持久化日志。

内容脚本执行前核对精确 tab/document、账号、页面类别、目标元素数量=1、可见性与操作范围；一旦 document 变化，旧元素引用失效。每一步重新从当前 DOM 定位，而非跨页面缓存 uid。

本机客户端对活动运行续租；服务和扩展在发起写动作前检查租约、停止标记及 deadline。客户端消失、点击停止或租约过期后不开始新动作。正在执行的浏览器点击不能撤销，只能记录并核对结果。单一命令队列，不积压一批未来发送。

读操作可在目标仍一致时有限重试。写动作超时、连接丢失或已进入 executing 后不自动换 requestId 重试。重连仅查询原 requestId 的日志及页面结果；无法确认则置 uncertain，阻止下一次沟通。

同一 requestId 的重复请求返回已有状态，不能再次点击。即使扩展/服务日志丢失，未知写结果也不作为未执行处理，需人工核对。

## 账号、常用语与已有 runner 的调整

第一阶段核实能否从合法可见 DOM 获得稳定账号标识。不能把显示姓名当作唯一 accountKey，也不读取 Cookie/隐藏认证状态补足。若无法可靠核验，报告明确能力缺口，写功能保持关闭；该缺口要在第一阶段结束时暴露，不能拖到最后发送才发现。

用户授权的是“本账号常用语第一条”，不是生成新文本。若已有会话可只读查看菜单，则在运行前读取并固定文本哈希；若没有可用会话，调整原 runner 的模板预读顺序：先以 first_saved_phrase 策略授权一次联系，再在该职位会话身份核对通过后读取第一条并固定哈希，之后才允许选择/发送。此时立即沟通可能已触发平台默认招呼，须单独记为 platform_greeting；若常用语为空，停止且不记成用户常用语已发。

后续职位发送前重新核对第一条哈希；条目变化即停止，不擅自发送旧模板。保持原文，不根据职位自动改写。

已沟通过的招聘者/职位默认跳过。回复、附件、联系方式按钮均不在工具能力内。核对会话时只读取目标会话必要信息，不把其他会话内容写进诊断包。

## 页面操作策略

搜索通过正常输入框 value/input/change 与页面搜索按钮执行；具体事件组合须基于真实页面验证。点击使用内容脚本 DOM 行为；若网站要求可信用户输入导致不生效，作为 DOM_ACTION_UNSUPPORTED 结束该技术试验，不静默切换 debugger/CDP 或模拟绕过验证。

立即沟通如果打开新标签，允许绑定唯一可证实由本次动作产生、同一 BOSS 域名且职位/会话身份匹配的新页；否则返回 TARGET_AMBIGUOUS。原职位列表页必须保留。

返回列表：优先重新选中原列表页；同页导航则使用已核验的 BOSS“职位”入口恢复搜索条件，并通过稳定职位 ID 去重。这里“退出”是离开会话，不是关标签、关浏览器或退出登录；首版无通用 history.back 或关闭标签工具。

## 诊断证据与可归因边界

默认记录每步时间、组件、工具名、目标 tab/document、脱敏前后 URL、选择器版本、元素匹配数量、执行阶段、耗时、结构化错误码与因果关联 ID。至少包含 MCP 到达、扩展收到、内容脚本收到、执行前检查、DOM 操作完成、后置条件结果。

生命周期事件从连接前的绑定初始化起持续记录，失败后不关闭记录器或自动刷新页面。URL 删除 query/fragment（需要的关键词等结构化字段单独记录）；账号和会话标识散列，凭证不记录。

失败诊断包存 private/diagnostics/<runId>/：events.jsonl、summary.json、目标区域的最小 DOM 摘要、适配器/依赖版本。业务成功记录存现有 data/ 或业务 SQLite。默认不保存整页 HTML、完整简历、其他聊天记录；第一条常用语原文只保留在既有私密模板存储，事件日志用哈希。

导航证据分三类：与本程序导航动作关联、浏览器报告变化但无关联动作、证据不足。结合 webNavigation transition 信息辅助分析，但不能仅凭没有本程序命令就断言是网站、用户或扩展导致。首版不承诺能获得所有站内 JavaScript 的调用栈；无法归因必须明确说明缺少的证据。

正常错误应能给出例如“request X 已到达内容脚本，在点击前因 documentId 改变拒绝”，而不是只有“连接失败”。服务断开时可关联扩展尚存日志；无论哪个组件失败，至少持久化最后已确认边界。

## 安全退出与恢复

用户停止后冻结写队列，记录未决动作，不关闭用户浏览器。Native port 断开时停止 HTTP 接入与新动作并退出自有服务；TypeScript 结束时先撤销运行租约再断开 MCP。扩展可保持已加载但不持续执行任务，无计划任务或后台轮询岗位。

保留原数据与配置，新增适配器模式；安装可卸载、依赖固定版本。上游原始源码保持只读参考，维护版放单独目录并保留许可和提交来源。

## 交给实现者的常规选择

目录命名、具体选择器、单次读取超时、日志轮转和文件布局可在遵守上述契约时确定并记录。首版暂定只读重试最多一次，单 DOM 动作 10 秒，消息结果观察 15 秒；过期只标记未知，不重发。租约/心跳具体数值应覆盖普通本机调度抖动，并经断连测试验证。

项目根目录当前无 Git 仓库，不为了提交此设计而擅自初始化 Git；文档落盘并由用户批准后进入实施计划。
