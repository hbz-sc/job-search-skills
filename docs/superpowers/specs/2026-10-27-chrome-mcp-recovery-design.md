# Chrome MCP 读取故障诊断与恢复设计

日期：2026-10-27。状态：用户已确认方案 A 及本短设计。

## 目标与范围

沿用 TypeScript、SQLite、官方 Playwright MCP 和用户已登录的日常 Chrome，定位“能列出 BOSS 标签、页面读取超时”的实际故障。优先保留用户页面与登录状态，随后完成深圳“AI应用开发工程师”搜索和一次使用第一条常用语的打招呼验证。

本次是既有实现的诊断与修复，不重做架构。无需模型 Key，不新建专用浏览器，不批量发送、不上传附件、不修改人工模式、不自动解除历史额度停止。用户此前明确授权的单岗位验证继续有效；真实页面身份、模板和当前限制未核实前不进入发送步骤。

## 已知事实与未决问题

- Chrome Default 已检测到官方扩展；上轮 browser_tabs 成功返回 BOSS 岗位页。
- browser_snapshot 和随后新会话中的最小代码读取均报告 MCP 请求超时。缺少服务端阶段证据，尚不能认定网站不支持 MCP。
- 当前客户端任意调用超时会断开服务；人工再次启动连接会生成新的授权页。不能把 MCP 协议初始化完成当成浏览器页面可读。
- 截图由岗位页变为深圳首页，但未采集标签关闭与导航事件，无法追溯断言原因。
- 适配器只接受岗位列表或聊天页；首页入口尚未支持，productionContract 仍未验证。
- 另一个电脑操作工具曾因无法可靠识别浏览器网址停止。此限制不作为 MCP 超时根因，也不通过其他工具绕过该工具的拒绝。

## Approaches

1. **A，用户已选：修复现有 MCP。** 保留登录与现有数据，增加可定位的连接诊断，再按证据修复。代价是扩展、MCP 和页面之间的故障必须逐层定位。
2. **B，未选：直接 Playwright/CDP。** 少一个扩展层，但需核实 Chrome 调试入口并改接入方式，不能保证消除页面读取故障。

## 设计

1. **单会话与明确阶段。** 一个运行只拥有一个 MCP 进程；初始化、等待用户授权、标签已连接、页面可读分别记录。等待授权与页面操作使用不同的时间预算。超时结束本次请求后不自动重连、不重放写操作；下一次诊断连接必须确认旧客户端已退出。
2. **分层只读探测。** 按标签列表、选中标签的元信息、最小 DOM 文本、搜索控件、受限范围快照逐项执行，记录每项开始、完成、耗时和原始错误类型。必要时只在 localhost 对照页面重复同一只读探测，以区分通用连接故障与 BOSS 页面故障。全页快照不作为第一步。
3. **标签生命周期证据。** 对已授权 BOSS 标签记录会话内稳定标识、导航、关闭、断连事件及程序操作意图。探测挂起时，尽可能从独立的本地事件日志判断停在哪层；不能将未收到事件视为事件未发生。日志只保存必需元数据，去除凭据和敏感查询参数，不导出 Cookie 或账号存储。
4. **首页恢复。** 页面能读后，支持识别已登录的 BOSS 深圳首页，通过实际可见搜索入口进入职位列表，保留用户其他标签。目标标签存在歧义时停止，不依靠当前焦点猜测。恢复导航有记录、有有限次数，不循环刷新。
5. **真实适配与一次验证。** 核实当前账号、城市、职位、会话身份和第一条常用语完整正文，使用真实页面证据校准现有适配器。遇登录、验证或额度提示停止；消息状态不明不补发。只有匹配正文出现送达/已读证据，才记一次成功。

## 验收与失败边界

- 本地测试覆盖分阶段超时、不会自动重连、标签恢复、脱敏记录和断开保留页面；已有测试继续通过。
- 实站记录必须明确区分：标签可见、内容可读、职位可搜索、常用语可读、消息送达。本地模拟通过不能替代实站验收。
- 若仍失败，输出最小失败调用、阶段与耗时、是否发生导航/关闭、已排除项和下一项待验证假设，保留页面，不重复要求重装或重登。
