# 方案 A：真实岗位分析修复设计

日期：2026-11-04。状态：用户已选择方案 A；本设计待确认，尚未进入实施。

## 目标和范围

让初学 Python/LangGraph 的用户能用自己的简历和真实招聘页面资料完成一次可理解、可复核的岗位分析。先解决模型连接、真实输入、逐岗进度和失败报告，再接网站搜索。

本次实施范围为方案 A 的第一阶段：本地真实资料分析。第二阶段 BOSS 搜索及完整 JD 采集另行设计，不把第二阶段完成作为第一阶段的验收条件。继续复用 Python、LangGraph、httpx、Pydantic，不引入新的框架。

不自动联系招聘方、不投递、不改简历、不操作 BOSS 任务锁、不安装或启动网站桥服务。测试允许使用固定样例，实战验收必须使用真实资料；两者明确标记。

## 已知现状

- week3.py 的 learn-model 默认读取 examples，用户容易把模型真实调用误认为岗位资料也是真实的。
- analyze_batch 一次处理整批，直到函数返回才显示节点完成；缺少逐岗进度。
- week3_model.py 将 401/403 统一为 MODEL_AUTH_FAILED，其余请求与解析异常大多合并为 MODEL_CALL_FAILED。
- 上一次真实资料请求返回 401。它是历史诊断结果，当前是否恢复要重新验证；不能以代码测试通过代替有效凭据验证。
- week1.read_jobs 规范化数据时丢弃采集时间、正文类型等来源元数据。
- 现有 preview 只采集列表基本信息，没有把完整 JD 自动交给第三周分析。
- 已有真实岗位文件是整理摘要，不符合本次“完整正文”的验收要求，不能只修改标记冒充完整正文。

## Approaches：已讨论的路线

1. A：先修真实资料分析，再接网站。优点是模型、资料和网站连接问题能分别验证，并与前三周学习内容衔接；代价是第一阶段仍需整理真实 JD。用户已选择。
2. B：一次恢复 BOSS、补详情采集并连通模型。操作连贯，但同时依赖网站登录、桥协议、锁状态及模型权限，定位问题更复杂。本次不采用。

## 建议的使用方式（以下细节为实现方提议）

增加两个入口，旧学习入口保持兼容：

```powershell
.\scripts\jobpilot.cmd check-model
.\scripts\jobpilot.cmd analyze --resume <真实简历.txt> --jobs <真实岗位.json> --limit 3
```

check-model 先做本地配置检查，再发一个不含简历、JD 的小型请求，验证配置指定的模型和所用 JSON 响应模式。明确提示会发起一次模型请求；不自动重试，不显示 Key、请求头或原始响应。它是独立诊断命令，不在每次 analyze 前增加一次额外调用；诊断成功也不保证后续服务永远可用。

analyze 的两个输入参数必须显式提供，没有样例默认值；启动时显示实战模式、文件路径、筛选城市和调用上限。不能通过路径名称证明数据真实，来源仍需人工核验。learn-model 保留教学默认值，但醒目标记是否正在使用内置样例。

## 资料边界

实战岗位采用 jobs 数组，沿用 jobId/title/company/city/salary/url/description，额外保留：

- capturedAt：带时区的 ISO 8601 采集时间。
- description_kind：original_full（页面完整正文）或 summary（人工摘要）。
- listing_status：observed_open、closed 或 unverified；页面可读不等于仍在招聘。

实战可分析项要求非空岗位名称、公司、城市、HTTP(S) 来源链接、合法采集时间和 original_full 正文。正文完整性由采集者核对，程序只校验字段，不声称自动证明完整。salary 可缺省，报告提示待确认；jobId 可缺省，以来源链接辅助去重。closed 项跳过模型并标为已关闭；unverified 可分析但报告必须提示在招状态待确认。

结构破损（非法 JSON、顶层错误、字段类型错误）属于输入错误，说明所在条目/字段并停止，不调用模型。结构正确但缺正文、来源或其他必需信息的单项列为 needs_info，列出缺失字段，其他合格岗位继续；summary 也列为待补完整正文。城市未知不推测为深圳，单列；城市不同按已有规则排除。无可分析项时零模型调用，不能把空结果描述为成功匹配。

使用独立实战输入校验，复用现有筛选和分析能力；不为加强实战限制破坏第一、二周练习。元数据必须从读取到 JSON/Markdown 报告保留。

真实资料留在 private，报告留在 output，均不进入版本控制。保留现有联系方式过滤及引用核对；该过滤不是完整匿名化，不宣称已删除所有个人信息。

## 模型调用与失败处理

继续从 .env 读取配置，并保留环境变量优先的行为。诊断只显示各字段是否配置、配置来源以及非敏感的模型和接口地址；地址展示必须去除潜在凭据和查询参数。有效 Key 需要用户在本地配置，修复代码不能生成或恢复账户权限。

区分配置缺失、401 鉴权失败、403 访问被拒、404 模型或端点不可用、429 限流/额度相关拒绝、网络连接错误、超时、服务端错误、JSON/结构错误及证据错误。不把单个 HTTP 状态解释成唯一根因；给出对应检查建议。只记录允许的错误代码、HTTP 状态及固定提示，不直接打印服务端正文或异常字符串。

401/403/404/429 视为本次批次的全局阻塞：当前项失败，剩余合格项标为未执行并说明原因，立即保存已有结果，不反复使用相同配置请求。单项超时、网络/服务端错误、结构或证据校验失败记为该项失败，继续下一项，仍受 limit 约束。没有自动重试。每次实际请求（包括失败）占用一次额度；缺字段、排除项、未执行项不占额度。

维持 limit 为 1—10，默认 1。配置和输入在首次模型请求前校验。用户主动取消时应清楚说明中断；本阶段不承诺跨进程断点续跑或强制终止后的结果恢复。

## 进度、图和报告

保留读取资料、分析岗位、保存报告三个教学节点，用受控进度事件或回调在 analyze_jobs 内输出每岗开始/结束；最终实现手段交给实施者。无需把每个岗位做成一个固定节点。

终端示例：正在分析 1/3：岗位名称；请求上限 3；本项完成，用时 N 秒。开始时告知请求超时策略，结束时报告已分析、信息不足、失败、未执行数量及总耗时，不用“节点完成”代表业务成功。

每份报告保留来源、采集时间、正文类型、招聘状态、模型名称、实际请求次数、逐岗结果和错误。保留 matched/gap/unknown 和原文证据校验，明确引用存在不能证明判断语义正确。JSON 供程序使用，Markdown 供人复核；不保存完整简历、密钥或原始模型响应。

正常分析 completed 与需补资料 needs_info 返回退出码 0；请求/配置/输入失败返回非零；混合失败或额度导致未执行为 partial，返回非零。输入错误可只给终端提示，未开始批次不伪造分析报告；开始分析后出现可处理错误则必须保存报告。

## 后续阶段

### 实施中由真实数据验证的调整（2026-11-04）

实际接口元数据表明该百炼模型默认思考会耗尽原有4000输出Token预算而不产生正文。仅对实测的 deepseek-v4.1-flash-1017 / 阿里云端点发送 enable_thinking=false；其他模型不注入此参数。新增 MODEL_OUTPUT_TRUNCATED 区分被截断的回答，不自动重试、不提高调用次数上限。

完整真实 JD 的职责、要求和加分项拆分后可超过原有20项。单岗位结构校验容量调整为40项，不裁掉超额要求；原文证据、字段类型和未知项追问约束保持不变。输出请求预算仍为4000Token。

第一阶段真实分析通过后，再设计并实施 BOSS 只读详情采集与分析衔接。那时重新检查扩展与锁的实际状态，不能沿用历史错误判断当前连接状态。
