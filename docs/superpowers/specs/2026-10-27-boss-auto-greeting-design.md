# Boss 直聘关键词搜索与常用语招呼工具设计

日期：2026-10-27  
状态：用户已于 2026-10-27 明确批准，进入实施计划阶段；本文不代表已完成开发或已执行发送。

## 目标与已确认选择

为用户本人在 Windows 本机运行：按关键词搜索 Boss 直聘职位，保存职位列表，依次进入「立即沟通」，选择指定常用语并发送，返回列表继续。遇到平台明确的沟通上限提示停止。

用户选择方案 A：TypeScript + Playwright + SQLite。用户要求阿里云模型 Key 先留空，等其创建 Key 并明确要求使用后再接入。

当前请求是选型后的设计阶段。既有 private/profile.json 的 manual_only 与旧记录暂不修改；批准设计后再规划实现。本轮不发送消息、不安装依赖、不启动服务。

## 方案比较与取舍

1. 自建 TypeScript + Playwright + SQLite：能按指定常用语和发送验证要求实现，需维护页面适配。用户已选择。
2. 改造牛人快跑：已有 Puppeteer/Electron 自动开聊能力，初始工作较少，但指定常用语及结果验证要核实。未选。
3. 油猴脚本：可使用当前网页登录状态，但跨页协调、断点恢复和结果记录要额外实现。未选。
4. OpenClaw + 本地容器：适合通用任务编排；本需求固定，引入更多运行与连接组件。未选。用户提及的 templators 未确认具体项目，不作功能假设。

## 边界

第一版只实现职位搜索、记录和固定常用语招呼；不自动回复招聘者，不交换联系方式，不上传或发送简历附件，不接入多账号，不创建定时任务，不承诺获得面试或 Offer。

不绕过验证码、风控或额度。登录/验证需要人工处理时暂停。不会把第三方项目的默认额度当成账号真实额度，不会自动在次日恢复。

## 建议的运行方式

以下为助手提出、待随本文确认的实现选择：

- Node.js + TypeScript；Playwright 负责浏览器操作；SQLite 直接使用数据库驱动，第一版不引入 TypeORM。
- 第一版通过本地命令行配置并运行，显示中文进度和停止原因；不先构建 React/Electron 管理界面。
- 专用、有界面的浏览器与独立持久化目录。用户首次手动扫码，后续复用登录态；不复制日常 Edge 的默认用户目录。
- 单进程、单账号、单个在处理的职位。启动时加运行锁，避免两个实例同时发送。
- 每轮由用户主动启动。支持只采集、不发送的模式，以及显式发送模式；只采集为默认。
- 在发送模式启动前展示本轮城市、关键词、常用语内容和停止条件；常规逐条发送不反复询问。
- 提供停止指令（Ctrl+C），每个操作有有限超时；停止后不启动下一次发送。正在提交的消息必须保留待核对记录。

## 搜索和职位范围

城市初始采用现有资料中的深圳；关键词由本轮任务配置提供，支持按顺序处理多个关键词。

按搜索结果顺序采集公司、职位、薪资、地区、经验、学历、职位链接、页面可得的职位与招聘者标识、职位描述和采集时间。缺失字段保留为空，不推断填写。

第一版不增加用户未要求的 AI 打分或薪资/外包硬过滤。保留用户选择的网页筛选条件，并在运行摘要中显示。对已沟通岗位、已处理记录、下架职位和无法核对身份的职位跳过或暂停处理。

列表可能重排或只渲染部分卡片。通过职位标识或规范化链接建立队列，逐屏采集与去重，不使用固定坐标或卡片序号作为身份。滚动/翻页无新增数据且达到有限重试次数时判为结果已耗尽并结束，不无限刷新。

## 常用语与发送流程

1. 开始发送前读取常用语；根据用户此前要求，初次选取第一条，显示完整正文并固定为本轮模板。
2. 后续按正文匹配该条常用语，不能因顺序变化而发送另一条。正文改变、缺失或无法读取时暂停，不擅自改写或由模型补全。
3. 每个职位在点击前重新核对职位身份与本地记录，并写入操作意图。
4. 点击「立即沟通」，处理实际页面表现：同页切换或新标签页。进入会话后核对公司、职位及招聘者信息，不能仅凭当前焦点发送。
5. 检查会话已有消息。若当前模板已经存在，不再发送；仅有平台默认招呼时，可继续发送用户指定模板一次。无法区分既有沟通与本次新会话时暂停该项，避免重复招呼。
6. 选择指定常用语。适配器需判断点击后是直接发送还是填入输入框：已出现对应消息则只验证；仅填入时才点击发送。不得无条件额外按 Enter。
7. 验证当前会话出现完整目标消息，并观察可见的发送状态。失败标记不算成功；只有消息气泡但无法确认提交结果时标为待确认。页面明确显示已发送/送达等可靠证据时记为已确认发送，并保存依据。
8. 返回保留的搜索列表页或恢复相同搜索条件，重新定位下一职位。

自动点击产生默认招呼与用户模板发送是两个事件，分别记录，不将它们混为一次已验证的模板发送。

## 记录、去重与恢复

SQLite 保存任务、职位、会话引用、模板及操作尝试。实现可自行确定表名；至少保留：账号本地标识、职位唯一键、可得的招聘者/会话键、模板摘要、操作阶段、时间、结果依据和错误原因。

业务状态包括：已发现、已跳过、准备开聊、会话已打开、准备发送、发送待确认、已确认发送、失败、额度停止、需人工处理。

发送前先持久化意图，发送后才记录确认依据。进程在提交期间退出或超时，恢复时优先查看对应会话，不直接再次点击发送。无法确认的项保留待确认，不自动重发。浏览器与本地数据库之间不能保证严格恰好一次，采用保守恢复减少重复。

对同一账号和职位去重；招聘者/会话标识可得时额外检查，防止不同职位进入同一个会话后重复招呼。仅公司名称相同不自动排除全部其他职位。

既有 CSV 记录作为历史参考，不覆盖或伪造迁移；只有能可靠匹配的已发送记录参与去重。无有效身份字段时需结合页面会话核对。

## 停止与异常

- 平台显示当日沟通上限：持久化停止原因与截图，立即停止新开聊和后续发送动作；不自动重试额度，不切换账号，不创建次日任务。
- 用户可设置本轮最大处理量，作为额外控制，与平台额度分开统计；未设置时仍受列表耗尽、平台提示和异常停止限制。
- 登录失效、验证或风控提示：暂停并提供明确原因，用户处理后主动恢复。
- 页面结构变化、会话身份不符、模板不符：暂停，不让模型自行决定给谁发消息或发送什么。
- 普通读取失败：有限重试；开聊或发送后的超时：先核对副作用，禁止直接重试写入动作。
- 连续异常达到阈值：停止并报告。具体等待时间、重试次数由实现者配置为保守默认值，不宣传为防封保证。

## 截图与可选阿里云多模态

核心流程通过网页 DOM、按钮文字及可见状态执行，不需要模型 Key。截图默认仅在失败、停止或验证需要时保存在本地，用于排查。

多模态能力作为后续可选适配层：模型可帮助解释截图片段和定位异常，但第一版不会凭模型输出直接发送，也不会把模型猜测作为已送达或额度恢复的证据。

设计预留的配置：

```dotenv
VISION_ENABLED=false
DASHSCOPE_API_KEY=
VISION_BASE_URL=
VISION_MODEL=
```

本文只是配置设计，不在本轮生成或安装运行配置。未配置 Key 时直接禁用模型调用，不阻断采集和常用语流程。具体地域、接口和模型在用户准备好阿里云服务后按官方文档确认，不预填猜测的端点。

未来启用前明确需要上传的截图范围；聊天截图可能包含个人信息，应只发送完成该次诊断所需区域。Key 保存在本地忽略文件中，不进入 Git、日志或截图。用户创建 Key 不等同于默认上传全部会话。

## 数据位置与现有工作区

保留 private/ 求职材料与原始简历；浏览器登录目录及密钥放在 private/ 下，数据库与任务记录放在 data/，诊断截图放在被忽略的本地目录。不得提交私人材料、会话内容、登录态和 Key。

upstream/ 继续仅作为参考，不自动执行其安装脚本或服务。正式实现时同步更新项目说明与发送模式表达，让新程序的显式发送模式与原来的人工分析流程可以并存，避免读取旧 manual_only 后行为不一致。

## 验证与验收

先在本地测试页面验证核心分支：同页/新页会话、常用语直接发送/填入、列表重排、重复职位与同一会话、上限提示、登录失效、发送超时及重启恢复。

然后在真实账号只采集，验证登录保持、关键词搜索和职位身份映射。设计批准不等同于该轮实际消息发送授权；真实发送验证在用户明确要求执行时，先限定一个岗位，核对正确接收人、正确模板与结果证据，再扩大至连续循环。

验收必须证明：没有 Key 可运行；只采集不产生沟通；仅向符合本轮范围的正确会话发送指定常用语；发送待确认项不会自动重发；遇上限停止且重启不会擅自恢复；用户可停止；退出后任务进度和异常可追溯。
