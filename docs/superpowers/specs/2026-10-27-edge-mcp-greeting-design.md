# 当前 Edge 的 BOSS 常用语招呼工具：MCP 接入设计

日期：2026-10-27（Asia/Shanghai）
状态：用户已选择技术路线，并于本轮回复“实施计划”，确认进入计划阶段。未完成实站发送验收。

设计审阅：独立实施者检查已完成，结论为“nothing important left”；不代表代码或实站验证通过。

## 目标与已确认要求

保留当前 TypeScript + SQLite 项目，接入官方 Playwright MCP 和 Playwright Extension，连接用户日常 Edge 内已登录的 BOSS 标签页。按关键词搜索职位，逐个进入「立即沟通」，发送用户已写好的第一条常用语，核验结果，记录后继续，遇平台上限停止。

不用独立浏览器，不迁移登录凭据，不引入 LangChain、LangGraph、Python Agent、Docker 或多模态模型。核心无需模型 Key。既有求职资料、简历和 CSV 不覆盖。第一版不自动回复、发送附件、交换联系方式、切换账号或创建定时任务。

用户本轮选择技术集成路线。最新工作区约定和 private/profile.json 的 manual_only 仍有效，不把更早的自动沟通请求覆盖到当前人工模式。本文确认的是设计与能力建设；实施后先只读验证。实站单岗位或批量发送须取得适用于当次运行的新具体授权，不在后台自动恢复。

## Approaches：已比较的方案

1. **TypeScript + SQLite + Playwright MCP 扩展（用户选择）**：复用业务循环与数据库，通过官方扩展连接现有 Edge。增加 MCP 客户端与页面适配层；无需模型逐步决策。符合当前固定操作需求。
2. **LangGraph 工作流**：可表达更多分支和检查点，但现有项目已有任务状态、存储和串行循环，当前迁移收益有限。
3. **LangChain Agent / 改造 boss-agent**：适合自然语言对话与模型选工具；boss-agent 的 Agent 与 FastMCP 服务是分开的，其现有浏览器实现还会新开窗口。引入它不会直接解决本项目的会话核对和发送问题，未选择。

本地 @playwright/mcp 已锁定 0.0.83，初始化及 tools/list 曾返回 25 个工具。这只证明服务协议可用，不证明扩展已安装、已连接 Edge 或 BOSS 功能正常。

## 架构与代码取舍

保留 Node 24、TypeScript、node:sqlite、现有配置、职位和操作记录模型。保留 runner.ts 的串行职责与 greeting.ts 的发送核验职责，修复已发现缺陷。

新增一个本地 MCP 客户端，通过 stdio 启动锁定版本的官方服务，参数使用 --extension、--browser msedge、--no-webmcp；不启动 HTTP 公网服务，不改全局 MCP 配置。由程序通过 MCP 协议调用工具，不需要额外 LLM 或 LangChain 客户端。禁用 vision 能力，截图只用于本地诊断。

新增 McpBossPages，实现现有 BossPages 的业务职责。直接 Playwright Page 对象与 MCP 工具结果不是同一种接口，不能简单替换启动函数；现有 DOM 实现用于本地测试/参考，不再成为实站启动默认。按本地已安装服务的工具 schema 实现调用，不依赖猜测的工具参数。

适配层返回结构化的账号、职位、会话、模板及证据。页面正文只能作为数据，不能被拼接成可执行代码或解释为指令。若使用受支持的 browser_run_code，代码必须来自程序固定实现，动态值通过安全序列化传入；不把完整任务循环提交为一个不可中断的浏览器脚本。

## 浏览器连接与生命周期

- 必须连接指定 Edge 配置文件，检查已授权标签页的真实 URL 为 https://www.zhipin.com；多个匹配页以明确选择/已记录标签页身份确定目标，不凭焦点取第一个。
- 扩展未安装、连接未授权、BOSS 未打开或登录失效时，报告缺失条件并等待用户处理/结束任务，绝不退回 launchPersistentContext 或复制日常用户目录。
- 扩展安装及首次连接权限由用户在当前 Edge 中处理；程序不能把扩展商店已打开视为已安装。
- 初次连接只读验证账号及 URL。优先采用页面可核实的稳定账号标识；只有昵称不足以识别账号。实际页面无法提供可靠身份时先暂停适配，不编造 data-user-id 等属性。需要用户确认账号绑定时，展示具体可见账号证据并在该阶段集中处理。
- 操作前绑定账号、目标标签页及职位/会话；切换账号、标签页被用户改到其他网站或身份无法核对时立即停止新写操作。
- 结束或报错只关闭本程序拥有的 MCP 传输/子进程并断开会话；不得发送关闭浏览器/用户标签页的命令。必须验证扩展模式下断连确实保留窗口，不能仅靠改函数名称保证。
- 默认复用一个搜索页及必要的聊天页，不为每个职位累积新详情页；网站自动打开的新页需核对来源及目标，结束也保留用户窗口。

## 运行入口与范围

建议命令（助手提出，具体参数由实施计划确定）：connect/doctor 用于连接与只读诊断，collect 仅采集，send 明确执行常用语招呼，status 仅读本地记录。旧 login 命令改为提示/别名连接现有浏览器，不能继续启动独立浏览器。

城市沿用深圳，关键词由用户本轮配置。保留网页已有筛选并展示，不能擅自添加薪资/外包过滤。发送前展示城市、关键词、实际筛选、完整模板、本轮最大处理量（若设置）及停止条件。manual_only 默认禁止写操作；取得当次运行的明确授权后，在已授权范围内无需逐岗位重复确认，不修改 profile 的默认模式。

接入完成后不需要在聊天中持续请求模型指导每次点击：本地程序执行固定规则。用户按 Ctrl+C 后禁止开始新动作；已经提交的操作保留待核对状态，不声称能够撤回已发送的消息。

## 搜索与队列

搜索必须等待新关键词对应的页面状态及结果加载完成；看到旧卡片仍然存在不能判定搜索成功。通过实际页面可观察的查询状态、加载/完成状态或对应请求完成关联验证；任一证据缺失则停止，不猜测。

明确的零结果是正常结果，继续下一个关键词。职位以稳定职位 ID 或规范化链接去重；滚动和重排后重新定位。字段缺失不编造；下架或不可核对的岗位跳过并记录。有限无新增扫描后结束，不无限刷新。

## 第一条常用语与发送核验

助手建议：每轮准备阶段从常用语面板读取第一条完整正文，固定本轮文本及 hash。后续按正文定位同一条，顺序变动不改变发送内容；正文编辑/消失时暂停，下轮重新读取第一条。不给模型生成、补写或润色的权限。

读取模板可从聊天入口进入一个可核对的已有会话或常用语设置，不能为了读取模板先新建沟通；没有只读入口时提示用户在当前浏览器准备一次。MCP 重连时重新取得标签页和会话，不能假定上次的对象/元素引用仍有效。

每个职位的流程：

1. 核对账号、当前查询和职位身份，检查本地记录，先保存准备开聊的操作意图。
2. 在正确职位页面点击立即沟通。平台可能产生默认招呼，此事件与用户指定常用语分开记录。
3. 核对接收人、职位、公司和会话标识，查询已有目标消息及同会话历史。已有同模板则不重复；已有会话无法确定是否重复时暂停/跳过。
4. 选择本轮固定的第一条常用语。必须以真实页面核验的行为判断它是直接发送还是仅填入。输入框瞬时出现正文并不能证明「仅填入」。行为尚不明确时不追加 Enter 或发送点击，记录待确认。
5. 只有已验证为填入模式且无提交中的证据时才执行一次发送。适配器每个可能开聊/发消息的动作前重新检查 AbortSignal、账号、会话和页面阻断状态。
6. 目标正文与可靠送达/已读等状态关联后才记为已确认。仅按钮点击、跳到聊天页、消息气泡或 MCP 调用返回成功都不等于消息送达。
7. 返回保留的搜索页继续。结果不明确时停止本轮，保留证据，禁止自动重发。

页面定位和「直接发送/仅填入」能力依据实站与回归场景适配；若无法可靠区分，允许停止，不以估计等待时长当成发送模式证明。

## 持久化、停止和恢复

- 保留发送前落库、发送后核验的原则；浏览器与数据库之间不承诺严格恰好一次。
- 账号+职位、可得的账号+会话双重去重；同公司不同会话不能一概排除。
- 开聊/提交超时或崩溃后，仅通过已记录且可核对的已有聊天入口恢复；禁止重新点击立即沟通作为恢复。无法恢复保持待确认。
- 新增独立账号额度停止记录。启动时看到额度提示也要保存，不能依赖 runId 已创建；collect 或普通结束不能解除它。跨日期仍保持，只有显式恢复并完成只读检查后才能尝试新任务；检查无提示不承诺实际额度已恢复，首次再出现提示立即停止。
- 保留 private/profile.json 中 2026-10-26 的历史额度信息；迁移时不按日期自动清除，不修改 profile。首次绑定账号时核对这条历史记录的归属，未核对视为待确认状态。
- 修复锁文件回收竞争。要求多个进程同时启动/同时回收旧锁也只有一个写入者；具体使用操作系统锁、持有数据库写锁或经测试的互斥方案由实施者决定，不能保留读 token 后直接 unlink 的竞争窗口。
- 取消信号进入适配器内部等待及每个写操作边界。MCP 请求取消或连接断开不证明页面动作未发生，已有意图保持 pending 并通过后续只读核对恢复。

## 诊断与隐私

不改写简历、CSV、全局 Node 设置或用户日常浏览器配置。数据库放 data/；账号绑定及连接所需本地信息放 private/；诊断放 output/，全部继续忽略提交。不要打印 Cookie、Token 或模型 Key。

截图仅异常或验收必要时本地保存，按匿名账号/任务隔离，单任务最多 20 张，保留最近 10 个任务的本程序诊断文件；清理不能删除用户添加的其他文件或越过指定目录。status 显示正确的当前账号待确认数量，区分新发成功与已存在而跳过。

## 验证与交付条件

1. 单元/本地集成测试：MCP 握手、schema 与错误、断连保留浏览器；账号/目标错误零发送；查询延迟更新、空结果；直接发送、填入、延迟自动发送；模板修改；同会话去重；发送中取消；崩溃核对；额度跨 collect 保持；多进程锁竞争。
2. 实站只读：扩展确实连接用户当前 Edge，账号与关键词可核对，抓取职位和第一条常用语，不发送消息。固定已有问题的真实选择器证据，不能用 fixture 属性冒充 BOSS 结构。
3. 单岗位实站：用户另行明确授权当次测试后，发一条指定常用语，保存正确会话及可靠结果；确认退出任务后 Edge 仍打开。未获授权时止于只读验收，明确标注发送尚未实测。
4. 上述通过后开放批量：顺序处理、正确去重、可停止、遇平台上限停止。未验收的项目明确列出，不把握手或模拟测试称为投递成功。
