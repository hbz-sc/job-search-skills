# 51job 独立投递流程 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有项目中实现深圳 Java 后端岗位的 51job 投递循环，首批最多尝试 50 个不同岗位，支持证据核验与无重复提交恢复。

**Architecture:** Python LangGraph 编排，51job 专属网页适配器执行明确业务动作，SQLite 分别存储 checkpoint 与投递账本。采用同仓库独立 `job51-page` 扩展、独立 native host 和 MCP 入口，避免扩展 BOSS 专用协议及其现有权限；只复用协议无关的 native framing，不复制 BOSS 聊天状态。

**Tech Stack:** 现有 Python 3.12、LangGraph 1.2.19、SQLite checkpoint 3.1.3、MCP、FastMCP、Edge 扩展、JavaScript、unittest、Vitest/Playwright。沿用两个现有虚拟环境，不升级依赖。

**Spec:** `docs/superpowers/specs/2026-11-10-51job-apply-design.md`（用户已确认）

## Global Constraints

- 保持同一个 job-search 项目，BOSS 与 51job 各自维护流程图。
- 51job 只投递，不点击「去聊聊」，不进入聊天扫码流程。
- 首轮最多投递 50 个岗位。50 是上限，不要求凑满。
- 首轮用固定关键词「Java后端开发」，深圳，主搜索结果列表；不采集侧栏推荐、不自动扩大城市或轮换关键词。
- 已派发后失败或结果未知仍占名额，不自动补投到 50 个成功。
- 使用网站已存在且明确的 Java 简历，不上传本地文件，不修改 profile 或 BOSS 发送模式。
- 私人材料、账号标识、截图在 private，投递数据在 data，不提交 Git。
- 实站首次投递计入同一批次预算；未核验成功前不继续剩余岗位。
- 不运行 upstream 安装脚本；实际站点结构不猜测；没有实站证据就标注未验收。

## Review Focus

1. 同名账号、账号退出重登、页签切换：身份或绑定变化必须暂停，不能把旧动作发给新页面（任务 2、4）。
2. 点击已成功但响应丢失、进程在两次点击之间崩溃：恢复只查证，不能重新提交（任务 3、4、5）。
3. 普通成功提示属于旧岗位、按钮已投递来自历史：不可记本批成功（任务 2、4）。
4. 空列表、无限滚动不前进、详情打开新页签：区分耗尽与读取失败，恢复原条件（任务 2、4、5）。
5. 首次点击才出现简历选择、附加问答或附件要求：同一名额内完成已知确认，无法确定则暂停（任务 2、4、5）。

- `scripts/{build-job51-extension.mjs,job51-bridge.cmd,register-job51-bridge.ps1,unregister-job51-bridge.ps1}`：构建与独立 native host 注册；注册支持 Edge，默认 dry-run，拒绝覆盖其他路径。
- `tests/python/test_job51_{policy,store,bridge,graph,cli}.py`、`tests/job51-{adapter,actions,controller,package}.test.ts`、`integrations/mcp-bosszp/tests/test_job51_bridge.py`：对应行为验证。
- `docs/job51/{page-observations.md,usage.md,acceptance.md}`：脱敏页面观察、操作说明、离线与实站验收结果。
- 修改范围仅增加主 CLI 分发、package.json 构建脚本、桥打包配置（需要时明确包含两个包）、README 的 51job 入口，以及新模块；不重构 BOSS。

共享数据字段由任务 1 固定为：Job={job_id,url,title,company,city,description,applied,can_apply}；View={account_id,binding,keyword,city,filter_fingerprint,jobs,exhausted,cursor}；Binding={session_id,tab_id,frame_id,document_id}；Evidence={job_id,account_id,observed_at,source,status,request_id}；ActionResult={request_id,phase,binding,value,error}；PreparedApplication={job_id,resume_id,status}。account_id 是本地稳定标识，不以显示姓名替代。PreparedApplication.status 为 ready、selection_required 或 needs_user_info；仅可证明首次点击只打开选择弹窗时，selection_required 允许 resume_id=null，否则资料不明确须暂停。确认提交前必须绑定已核验的简历标识。

命令中 Python 路径均相对执行工作区根目录；如果使用 worktree，定位主工作区已有虚拟环境的绝对路径，不复制私密配置或运行数据库。测试不访问生产账号。

## 自检与执行方式

规格中的页面观察、岗位筛选对应任务1/2；独立平台和桥对应4；50上限、幂等对应3/4；完整图与恢复对应5；真实验证、私人记录和BOSS回归对应6。五类 Review Focus 均有明确测试归属。未将真实页面未知信息写成已观察事实。

建议 Native 执行：当前会话逐项实现，最终独立审阅。网页结构、桥协议和恢复状态相互依赖，保持一个实施者能减少交接偏差。用户尚未选择执行方式；按 writing-plans 技能，先交付本计划供审阅和选择，再开始实施。
